From tabular data to raster

Tabular data

  • Wickham (2014): Tidy tabular data: Each variable is a column, each observation is a row, and each type of observational unit is a table.
  • Below is a dataset from Baltagi and Baltagi (2008)
  • Observation is a state in a particular year
  • Variable is a measured parameter (see below)
  • Start with Wickham’s fundamental definition - this is the foundation
  • Emphasize this is about data structure, not just organization
  • The Produc dataset is a classic econometric panel dataset - good for demonstrating concepts
  • Make sure students understand what constitutes an “observation” vs a “variable”

Long tables have a lot of repetitions:

  • state: 815 values, but only 48 unique states
  • year: 815 values, but only 17 unique years
  • Total: 8’150 values in the table
  • Walk through the calculation step by step
  • 816 total entries for state, but only 48 unique states
  • This repetition is characteristic of long/tidy format
  • Great for analysis but wasteful of memory
  • This leads naturally to why we might want wide format for raster data

Dataframe → Matrix

The gain from converting to a matrix:

  • A dataframe is a list of column vectors — each column is a separate object in memory
  • A matrix stores all values in one contiguous block of memory
  • All values have the same type (dbl) → no per-column type metadata, enables vectorized operations
  • Row/column names are stored once separately, not repeated
  • Limitations:
    • Only advantageous if the data is densely populated (few NAs)
    • Only relevant if the data is large
     ALABAMA ARIZONA ARKANSAS CALIFORNIA COLORADO
1970     4.7     4.4      5.0        7.2      4.4
1971     5.2      NA      5.4        8.8      4.0
1972     4.7     4.2      4.6        7.6      3.6
1973     3.9     4.1      4.1        7.0      3.4
1974     5.5     5.6      4.8        7.7      3.8

  • Homogeneous data types enable matrix operations

  • Matrices are stored contiguously in memory - much faster access

  • This speed difference becomes enormous with large raster datasets

  • Matrix operations are highly optimized and often vectorized

  • If data is mostly missing, wide format can be wasteful

  • For small datasets, the overhead isn’t worth it

  • Remote sensing data is typically large and dense - perfect for this approach

  • This sets up why raster format is natural for imagery

Imagery Data

Images are Rasters

  • The spatial raster data model represents the world with the continuous grid of cells (a.k.a. pixels)
  • This data model often refers to so-called regular grids, in which each cell has the same, constant size
  • Through its inherent model, this data naturally fits into the wide data structure
  • This connects directly to the previous lesson on wide vs long data
  • Emphasize that raster data is inherently a grid/matrix structure
  • Each pixel has a fixed location - this is why wide format makes sense
  • Regular grids are the foundation of most remote sensing data
  • We will focus on the regular grids only. However, several other types of grids exist, including rotated, sheared, rectilinear, and curvilinear grids (see Chapter 1 of Pebesma and Bivand (2023)).

Types of raster data

  • Raster datasets usually represent continuous phenomena such as elevation, temperature, population density or spectral data.
  • Discrete features such as soil or land-cover classes can also be represented in the raster data model
  • Distinguish between continuous (elevation, temperature) and discrete (land cover classes) data
  • Both can be stored in raster format, but analysis approaches differ
  • Most remote sensing applications deal with continuous spectral values
  • Discrete classifications often result from processing continuous data

A more complex example: Spectral data

  • Typically, RS imagery consists of more than 1 band
  • In this case, the data is stored in a 3 dimensional array (where band is the 3rd-dimension)
  • A RS image can contain any number of bands.
  • The most well known type of RS imagery consists of 3 Bands from the red, blue and green spectrum
  • Move from 2D (single band) to 3D (multi-band) concept
  • Each band captures different wavelengths of electromagnetic spectrum
  • RGB is familiar to students - good starting point
  • Modern satellites can have hundreds of bands (hyperspectral)

Each band is a 2D matrix

Multispectral Datasets

  • Multiband datasets usually capture different parts of the EM spectrum
  • E.g. the Landsat image from the previous example has 6 bands capturing the following wavelengths:
    • Band 1: Blue (0.45 - 0.52 µm)
    • Band 2: Green (0.52 - 0.60 µm)
    • Band 3: Red (0.63 - 0.69 µm)
    • Band 4: Near-Infrared (0.77 - 0.90 µm)
    • Band 5: Short-wave Infrared (1.55 - 1.75 µm)
    • Band 7: Mid-Infrared (2.08 - 2.35 µm)
  • Point out that Band 6 (thermal) is missing from this list - was not included in this dataset
  • Each band serves different purposes: visible for true color, NIR for vegetation health, SWIR for moisture
  • These wavelength ranges are carefully chosen based on atmospheric windows and target phenomena
  • Students will learn to use different band combinations for different applications

NirGB Image

Representations of multispectral data

  • A true color image is created by using the Red (3), Green (2) and Blue (1) Band and mapping these to RGB
  • A false color image is created by mapping other bands to RGB
  • True color: what our eyes would see if we were there
  • False color: reveals information not visible to human eye
  • NIR false color is very common - vegetation appears red because it reflects strongly in NIR
  • Different false color combinations highlight different features (water, urban areas, etc.)

The SpatRaster Object

What makes a matrix a raster?

  • We established that a raster is a matrix of values
  • But a plain matrix has no spatial meaning — it does not know where on Earth it is
  • A SpatRaster (terra) extends a matrix with three pieces of spatial metadata:
    • Extent: the geographic bounding box (xmin, xmax, ymin, ymax)
    • Resolution: the size of one pixel in CRS units
    • CRS: the coordinate reference system — the spatial reference frame
  • Together, extent + resolution + CRS allow every pixel to be located precisely on Earth
  • This is the key conceptual bridge from the matrix world to georeferenced spatial data
  • Without CRS + extent, a raster is just a matrix floating in space
  • All spatial operations (project, resample, mask, extract) rely on these three being set correctly

Printing a SpatRaster shows all metadata

  • Ask students: if res() returns 0.00833 degrees, how large is a pixel in meters at the equator? (~930m)

Coordinate Reference Systems

What is a CRS?

  • A CRS defines how coordinates relate to real locations on Earth
  • Two broad families:
    • Geographic CRS — coordinates in degrees (longitude, latitude) on a spherical Earth model Example: WGS84 (EPSG:4326), used by GPS
    • Projected CRS — coordinates in meters (or feet) on a flat (2D) surface Example: EPSG:2169 (Luxembourg), UTM zones
  • Most downloaded satellite data uses WGS84; spatial analysis often requires a projected CRS
  • The Earth is curved, so projecting it onto a flat surface always introduces distortion
  • Geographic CRS is fine for storage and display; projected CRS is needed for distance/area calculations
  • A focal window of 3×3 in degrees is not 3×3 meters — this is why CRS matters for map algebra

Checking the CRS

crs(r, describe = TRUE)   # human-readable summary
    name authority code  area             extent
1 WGS 84      EPSG 4326 World -180, 180, -90, 90
  • describe = TRUE gives a concise one-line summary: name, authority, code
  • The full WKT is what gets embedded in file metadata — this is what other software reads
  • If CRS is missing (NA), spatial operations may silently give wrong results

Reprojecting with project()

  • Use project() to reproject a raster to a different CRS
  • The raster is resampled so that pixels align to the new grid
r_projected <- project(r, "EPSG:2169")

res(r)           # original: degrees
[1] 0.008333333 0.008333333
res(r_projected) # projected: meters
[1] 771.9715 771.9715
  • After projecting to EPSG:2169, res() returns meters (~927m here)
  • This is the same physical pixel size expressed in a different unit
  • project() involves interpolation, which slightly modifies values — only reproject when necessary
  • We will use this in Lesson 2 when we need focal windows in real-world units (meters)

Why CRS matters for analysis

Geographic (degrees)

  • Resolution of 0.00833°
  • A focal window of 3 cells ≈ 0.025°
  • Pixel “size” varies with latitude

Projected (meters)

  • Resolution of ~927m
  • A focal window of 3 cells = 2.8 km
  • Pixel size is constant everywhere
  • This difference becomes critical in Lesson 2 when we create focal windows
  • focalMat(r, d = 2000, "circle") requires the raster to be in meters to mean “2km radius”
  • Always check crs(r, describe = TRUE) and res(r) before doing spatial analysis

NoData in Raster Data

What does NA mean in a raster?

  • In tabular data, NA means “value not recorded” for an observation
  • In raster data, NA has additional spatial meaning:
    • Outside the study area — pixels beyond the boundary of interest
    • Other, such as Sensor failure, Atmospheric effects etc.
  • NA pixels are not skipped in raster algebra — they propagate: 5 + NA = NA
  • This propagation behavior is different from what students may expect from tabular workflows
  • In raster operations, NA cells stay NA unless explicitly handled (na.rm = TRUE, mask, ifel)
  • Students will encounter this immediately when working with real satellite data (cloud cover)

How NAs arise: study area boundaries

r <- rast(system.file("ex/elev.tif", package = "terra"))
lux <- vect(system.file("ex/lux.shp", package = "terra"))

# show the bounding box vs the actual data extent
plot(r, main = "Values within Luxembourg boundary")
plot(lux, add = TRUE)
  • The raster grid is always rectangular — but the real data often covers an irregular shape
  • Cells outside the country boundary are NA
  • The bounding box (ext()) covers the whole rectangle

Working with NA: is.na() and mask()

# identify where NAs are
na_raster <- is.na(r)
# mask: set cells outside a vector boundary to NA
r_masked <- mask(r, lux)
# replace NA with a specific value (e.g. 0)
r_filled <- ifel(is.na(r), 0, r)
  • is.na() returns a Boolean raster: 1 where NA, 0 elsewhere
  • mask() takes a vector or raster boundary and sets everything outside to NA
  • ifel() is the raster equivalent of ifelse() for cell-by-cell conditional replacement
  • na.rm = TRUE in aggregation functions (mean, sum) ignores NAs, like in base R

Edge effects in focal operations

  • Focal operations require a neighborhood around each cell
  • Cells at the raster edge do not have a full neighborhood
  • By default, this produces NA in the output border
r_foc     <- focal(r, w = 3, fun = mean)
r_foc_pad <- focal(r, w = 3, fun = mean, fillNA = TRUE)

plot(r_foc,     main = "fillNA = FALSE (default)")
plot(r_foc_pad, main = "fillNA = TRUE")
  • fillNA = TRUE pads the border with NAs before computing, so the output has the same extent as the input
  • For large windows the effect is more pronounced — a 11×11 window loses 5 cells on every side
  • This will matter in Lesson 2 when we compare focal window sizes

Reading and Writing Rasters

Common raster file formatsCommon raster

Format Extension Notes
GeoTIFF .tif Universal standard; stores CRS, extent, metadata
JPEG2000 .jp2 Used by Sentinel-2 (ESA); lossy or lossless
NetCDF .nc Common in climate science; supports time dimension
HDF5 .h5 / .he5 Used by MODIS, Landsat Collection 2
Cloud-Optimized GeoTIFF .tif (COG) GeoTIFF optimized for remote/cloud access
  • Students will encounter JP2 in Lesson 3 when working with Sentinel-2 SAFE files
  • NetCDF is important for temporal datasets (e.g. ERA5 climate reanalysis)
  • COG is increasingly important for cloud workflows (reading subsets without downloading the whole file)
  • GeoTIFF is the recommended format for most workflows
  • All formats are read/written by GDAL — terra uses GDAL under the hood

Reading rasters from disk

# read a single-band GeoTIFF
r <- rast("data/elevation.tif")

# read a multi-band GeoTIFF
l7 <- rast("data/L7_ETMs.tif")

# read one specific band from a multi-band file
band3 <- rast("data/L7_ETMs.tif", lyrs = 3)
  • rast() reads all spatial metadata automatically (CRS, extent, resolution)
  • The data is not loaded into RAM by default — terra reads values on demand (lazy loading)
  • Use values(r) or as.matrix(r) to force loading all values into memory
  • Lazy loading is critical for large rasters that don’t fit in RAM
  • terra processes large rasters in chunks internally — students don’t need to manage this
  • Printing the object shows “source: …” confirming it’s backed by a file, not just in memory

Writing rasters to disk

# write to GeoTIFF (all metadata is preserved automatically)
writeRaster(r, "data-out/elevation_out.tif")

# overwrite an existing file
writeRaster(r, "data-out/elevation_out.tif", overwrite = TRUE)

# specify the data type explicitly (default is Float32)
writeRaster(r, "data-out/elevation_byte.tif", datatype = "INT1U", overwrite = TRUE)
  • CRS, extent, resolution, band names and data type are all written into the file
  • Any software that reads GeoTIFF (QGIS, Python/rasterio, ArcGIS) will read the same metadata
  • Choosing the right datatype matters for file size — covered in Lesson 3
  • This is intentionally brief — the datatype/scale/offset topic is fully developed in Lesson 3
  • Reinforce: the file stores everything needed to reconstruct the raster — students don’t need separate sidecar files
  • Warn about overwrite = TRUE — it silently overwrites without a prompt
